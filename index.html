What I own on a project

Most teams split a blockchain product across a contracts dev, a backend dev, a frontend dev and someone who babysits the nodes. I architect and build across all of it, so the pieces are designed to fit from day one.

Protocol architecture

Token and incentive design, upgrade strategy, access control and failure modes, written down before a line of Solidity. AMMs, lending, staking, vaults (ERC-4626), DAOs and multisig treasuries.

Smart contracts that survive audit

Solidity on EVM chains and Rust on Solana, built test-first in Foundry and Hardhat with fuzzing and invariant tests. I review for reentrancy, oracle manipulation, front-running and access-control flaws before anyone else has to.

Zero-knowledge features

zk-SNARK circuits in Circom and SnarkJS for private transfers, identity proofs and rollup-style batching, with an understanding of where zk-STARKs fit better.

Cross-chain and interoperability

Bridge contracts, cross-chain messaging and multi-chain deployment pipelines across EVM networks, Solana, Cardano and Hyperledger Fabric.

The product around the chain

TypeScript backends (Node.js, NestJS, Express) on PostgreSQL and Redis, subgraphs on The Graph, and React / Next.js frontends with Wagmi and Viem wallet flows that non-crypto users can actually finish.

Production infrastructure

CI/CD in GitHub Actions, Dockerised services, NGINX, node operations and monitoring on AWS, Azure, GCP and DigitalOcean.

How an engagement runs

The same five stages whether it’s a two-week audit or a six-month protocol build. You get a written artifact at the end of each one.

  1. Discovery & threat model

    What the system must do, who might attack it and what failure costs. Output: a short brief and risk list.

  2. Architecture

    Contracts, data flow, off-chain services and upgrade path on one diagram. Output: an architecture doc you can hand to any engineer.

  3. Build, test-first

    Contracts with unit, fuzz and invariant tests, then the backend and frontend against a local fork. Weekly demos.

  4. Internal audit

    A line-by-line security pass with findings and fixes written up, so an external auditor starts from a clean base.

  5. Deploy & operate

    Testnet, then mainnet with verified contracts, monitoring and a hand-over runbook.
